## Camera interruption of Wi-Fi association

A camera capture deliberately stops STA for contiguous camera DMA memory. A preceding asynchronous WiFi.begin had already returned, so no SDK call was running, but the association flag remained set. Maintenance waited25seconds and charged a false failure plus4seconds backoff. Successful radio shutdown now retires that obsolete association under existing camera/HTTP exclusion. It retains real failure history and normal connection cooldowns. Camera teardown still restores its memory reserve before reconnection.

The regression uses actual production camera, admission and Wi-Fi maintenance functions. Old177 fails the cancellation invariant; the fix passes135 checks. Existing camera DMA/priority, Wi-Fi and diagnostic suites pass. These controlled host tests do not establish physical RF reliability.

## Stale OTA discovery and coordinator ownership

A read-only September17 ROM snapshot, decoded with177's actual codecs, showed closed DISCOVERY generation4 with origin mqtt_cmd, no firmware target or destructive attempt, alongside admitted unresolved nightly_20260915 and a known LCD-due hint. Deferred0916 and observed0917 were retained. This is a coordinator bookkeeping blockage; it is not evidence that USB or Wi-Fi caused that manual refusal.

178 admits a narrowly proved, charged recovery of closed read-only discovery. It verifies authoritative pending ownership/timezone/due time, known storage state, fresh local/peer boot health and original peer lease. An eligible later pending can adopt an earlier closed discovery; an existing own pending can retry it. Target-free discovery requires zero destructive history. Canonical discovery retaining a previously resolved comparison target instead requires fresh proof of that completed/current pair and preserves its target and accounting. Actual unfinished PREFLIGHT/APPLY/DEFERRED targets remain on their existing paths.

Each manifest request is reserved durably before network access. Manual recovery can use the ordinary allowance of a genuinely later UTC day only when its existing not-before has arrived; it never replenishes the current day or lifts deferred-path restrictions. A successful verified no-update pair closes discovery accounting before committing coordinator completion. Interruption between these writes retains the pending request and requires another charged check. It does not claim an old firmware transfer succeeded. A pending claimed after the caller's original state snapshot is also reconciled, avoiding inheritance of the previous pending ID.
