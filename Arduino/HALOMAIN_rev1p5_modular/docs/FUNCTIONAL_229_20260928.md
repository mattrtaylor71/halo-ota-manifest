## Findings and limits

The important unresolved issue is **voice/list first-attempt response timeout**.
It reproduced on 229 at RSSI −49 dBm, so poor signal alone does not explain it.
The existing shopping-list voice path uses a 1,500 ms response-read timeout.
The cloud accepted the exact payload about 0.35 seconds after the native timeout
and completed it once. The device saved the recording and retried about five
minutes later. Case 13 received HTTP 202, deleted the saved copy, cleared pending state
and both retry arms, and slept with the LCD dark. It remained quiet for 127.57
seconds afterward, with no host commands or taps. Successful recovery does not
erase the original timeout. Final cloud verification found two ingest receipts
but one unchanged completed job and one worker execution. The exact receipt is
in the acceptance index. Ambient voice content produced no backend action or
shopping-list mutation in the scoped original-window readback.

A separate wake at RSSI −82 dBm hit a 15-second SNTP timeout. The initial test stopped
before capture; it is retained as image 10. Ordinary capture was then tested
without demanding a fresh SNTP response first, while keeping actual enqueue,
delivery and sleep assertions. Image11 passed. Another wake's pre-sleep diagnostic
report reached its response-header deadline; no successful report is claimed for
that attempt. Cloud telemetry retention is independently proved from health 08.

Two telemetry defects found on 228 were fixed in 229: optional forwarding no longer
requires an unrelated initial-link latch after a valid recent PONG, and the USB
readout fits the bounded output buffer. All user-action, transfer and sleep
exclusions remain. Reading the system rail does not establish battery percentage,
charger state, USB-versus-cell source, calibration accuracy or shutdown thresholds.

No new phone provisioning, factory reset, physical power interruption, new OTA
transfer, unattended 2 a.m. execution, battery-only run or full physical gesture/
visual review was performed. Strict failures caused by damaged diagnostic lines
remain recorded; later independent evidence is not substituted into those runs.
