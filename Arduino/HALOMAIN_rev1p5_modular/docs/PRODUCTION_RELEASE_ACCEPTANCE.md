## One finite matrix

Bind exact source/build, both image hashes, starting full policy, test pair, stimulus, original deadline and cleanup owner before each case. Reuse existing operators and component checks. A missing witness is incomplete evidence; an observed contrary result is a failed case. Neither becomes a pass through repeated observation. Hardware acquisition refusals remain separate from OTA attempts.

Shipping disables even the `OTA_BENCH op=read` command used for the earlier six-chunk full-record queries. Use the available ordinary/State/H4 and identity evidence during the case. If full 768-byte policy readback is required, bind a separately bounded, non-mutating flash/NVS read after all case owners close, after verifying the actual device permits it. Do not enable bench commands or send a disabled reader and count its refusal as a firmware failure. Archive read-time reset effects separately from the preceding autonomous boot.

## Starting state and legitimate acceleration

The designated pair's archived 101 stop left generation 318, `AUDIT_ONLY`, `DEFERRED`, reservation 0 and work 0 on UTC day 20706. It armed September 10, 2026 at 02:00 Pacific, but that instant is still day 20706: the first later-day credit opportunity is September 11 at 02:00 Pacific. Manual OTA cannot bypass this state. Firmware replacement, a timezone change and power cycling do not create credit.

For efficient new production acceptance, an explicitly documented **factory transition** is a separate valid baseline: archive the old records first; use reviewed factory installation/provisioning on the designated pair; verify absence of both new policy and retained legacy debt rather than deleting only one ledger. Fresh absence permits `start_discovery()` to commit its normal 120-second network reservation from the 40-minute daily allowance. Never repeat this transition inside a failure/retry case or present it as automatic recovery from the retired bench ledger.

The normal calendar uses `NightlySchedule.h` and the saved POSIX timezone. Shipping receives timezone only from the existing successful claim response (`timezone` or `tz`); the USB `settz` command is test-only. A supported per-device temporary timezone can move local 02:00 nearer for the calendar-path case if the actual backend supports delivering it. Preserve UTC time and all debt, document the configured zone, then restore and read back Pacific. This is calendar-path equivalence, not proof of a Pacific wall-clock overnight run, and it cannot accelerate the strictly later-UTC-day budget rule.

The later-day rule can also be tested efficiently as an explicitly **new saved-NVS fixture case**. After the preceding case is finished and archived, prepare a valid exhausted previous-UTC-day record for an actual newer, uninstalled target through the exact production codec/state rules. Keep a valid deferred phase, no active reservation, no bench/one-shot state, coherent target/history/timestamps and a due normal-maintenance boundary. This is synthetic prior state with genuine current time; it must not be called an observed overnight failure or an in-case refund.

Use the existing validated NVS parser to find the unique `ota_coord/retry_v1` blob and all its chunks in the current capture. Replace only its same-size 768 bytes plus required NVS data/entry CRCs; preserve unrelated namespace data, page layout and ownership. Revalidate both canonical and NVS CRCs, logical chunk joins, full expected byte diff and actual partition/security state. An old test's hardcoded flash offset is not an installation plan. Only a separately bounded write/readback of the exact affected sectors may install this declared fixture. Boot the unchanged shipping binary, prove it reads the intended fixture, then let a real normal calendar wake perform rollover and OTA admission. No further fixture edit, grant or clock change occurs during that case. Preserve before/fixture/after images and restore the intended customer timezone afterwards.

The shipping manifest resolver currently uses compile-time default/channel configuration, not a runtime per-device channel. Stage immutable artifacts privately where possible, but do not claim that staging redirects the candidate's production latest fetch. Bind the actual supported delivery route before testing; do not fault global production latest to create a test case.

A canary profile may change only its compile-time OTA route while retaining all shipping policy limits and disabled test controls. Label that routing difference. For a canary-to-final production transition, stage both final versioned production manifests and immutable binaries first; the private canary latest may point to those exact final bytes. After reboot, the final production image must reconcile its persisted target through its own production versioned manifest, without requiring a global latest promotion or the old canary route. This route transition and the final exact-byte health check require their own evidence; they do not turn a canary build into an identical production build.

The available Uno actuator can tap only. The user supplies real hotspot toggles and full power cuts; there is no established relay or router fault injector. A hotspot toggle demonstrates disconnection, not a server header/body trickle. Exact slow-response testing needs a scoped external network/backend capability or must remain explicitly unmeasured.
